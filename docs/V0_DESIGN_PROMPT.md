# v0 design brief for VARSHIQ

The user requested v0 for UI/UX. Direct access from the local browser failed DNS resolution on 2026-11-02 and no v0 connector is installed. This prompt is prepared for the user's v0 workspace; current UI must not be claimed to be v0-generated.

Create a professional responsive ClimateTech operations interface for VARSHIQ: Predict the Rain. Harvest Every Drop. The core user flow is real building selection, rooftop verification, live forecast, event harvesting, WaterTwin tank simulation, storage comparison and downloadable assessment.

Use React, TypeScript, Tailwind, accessible native controls, restrained purposeful motion and reduced motion. Ink sidebar, warm neutral canvas, teal/blue accents, locally licensed DM Sans/Manrope fonts. Clear units, timestamps, linked provider credit and verification chips. Mobile390x844, tablet768x1024, desktop1440x900.

Use the existing backend API contract and modular page structure. No fictional properties, hardcoded rainfall statistics or decorative fake charts. Empty state encourages actual registration. A geospatial footprint is an estimate; usable catchment only becomes owner-recorded field verified with measurement evidence.

Design dashboard, building map, registration, verification, rainfall, WaterTwin and optimiser screens with loading, empty, partial, error, success and permission states. WaterTwin shows runoff, first flush, collection losses, starting volume, demand supplied/unmet demand, ending storage and overflow. What-if scenarios are labelled estimates and do not change measurements. Historical reanalysis is labelled separately from IMD/gauge observations. Include explain-this-result panel and report-download flow. The assistant must show backend sources. Future modules are explicitly unavailable.

Provide reusable components and tokens that can be integrated into the functional existing frontend; preserve all data flows and safety boundaries.
