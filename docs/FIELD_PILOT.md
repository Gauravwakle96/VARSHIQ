# Field pilot and demonstration

The software checks do not substitute for an authorised field pilot. Start with two houses, two commercial properties and one apartment/community context. Register each only after owner permission; record whether municipal aggregate sharing is permitted. Keep addresses, geometry, photographs and measurements inside the private workspace.

For every property, record the selected coordinates and source, connected rooftop catchment measurement and method, roof runoff coefficient/reference, first-flush arrangement, collection-loss assumption, tank capacity, dated current-volume reading, intended non-potable daily demand and installation-space evidence. A footprint polygon estimates a building outline; it does not verify the connected roof. A registrar's field-evidence label is not independent engineering certification.

Use a measured rainfall gauge if comparing forecast accuracy. Record the actual rainfall/collection interval, instrument or measurement method, overflow, first-flush diversion, consumption and maintenance conditions. Tank rise alone cannot establish collection where consumption, leakage or transfers occur. Calibration requires sufficient reliable independent observations; leave it ineligible until those exist.

Before field installation, obtain qualified review of structural loads, contamination risks, treatment, recharge suitability, local permissions and applicable engineering standards. The application exposes assumptions and missing evidence; it does not issue those approvals.

## Suggested six-minute demonstration

1. Search CSN or the actual pilot locality, select its real coordinates/building, and show the source attribution. Switch to Pune to show distinct weather coordinates, then return to the pilot property.
2. Open an authorised property and show its connected-catchment evidence, tank reading and intended-use demand. Explain which values are measured, entered or geospatial estimates.
3. Retrieve tomorrow's forecast and hourly timeline. Show the exact local date, provider/retrieval time and separate precipitation probability.
4. Run WaterTwin. Inspect gross runoff, one diversion per event, collection losses, demand supplied/unmet demand and explicit overflow. Change a tank/demand scenario and compare its labelled forecast estimates.
5. Record an actual observation if available, inspect maintenance/readiness, and show performance/calibration eligibility. Show missing groundwater evidence honestly.
6. Compare registered properties and actual quoted storage options, then download the assessment PDF with sources and assumptions.

If the forecast is dry, show the actual zero forecast and real historical context. Do not add rain or fabricate collection to improve the presentation. A deliberately entered what-if scenario must remain labelled as a scenario. If the provider fails, disclose any stale cache and use the source-status/retry flow.

Prepare the live integration before the event and retain dated verification evidence. A public hackathon presentation should use owner-consented information or redacted reports; private owner records must not be published simply because a code repository is public.
